# Новая lip-sync технология: разведка и проверка (сентябрь 2026)

Задача: найти новую технологию lip-sync и проверить её.
Проверка выполнена в облачном Linux-контейнере **без GPU** и **без доступа к HuggingFace/ModelScope**
(egress-прокси блокирует оба хаба), поэтому реальный инференс здесь невозможен.
Всё, что можно было проверить фактически — проверено по исходному коду репозитория,
по техотчёту в самом репозитории и запуском кода на CPU. Остальное помечено как `NOT_MEASURED`.

## Вердикт

| Кандидат | Что это | Статус |
| --- | --- | --- |
| **LongCat-Video-Avatar 1.5** (Meituan, 21.05.2026) | Новый SOTA-класс: генерация всего видео аватара из фото+аудио, не «переклейка рта» | `WARN` — код и лицензия проверены, железо под вопросом |
| **HighSync** (arXiv 2605.16918, 2026) | Классический lip-sync (правка рта в готовом видео), первый нативный 512×512 | `NOT_MEASURED` — код есть, проект одного автора |
| LatentSync 1.6 (ByteDance) | Текущий де-факто baseline | Стагнирует: последний релиз — июнь 2025 |

Главная находка — **LongCat-Video-Avatar 1.5**. Это не инкрементальное улучшение Wav2Lip-линейки,
а смена слоя в пайплайне: модель не правит губы в готовом ролике, а рождает ролик целиком
из референс-фото + аудио, включая тело, руки и мимику.

## Что доказано (проверено фактически)

Проверено клонированием `github.com/meituan-longcat/LongCat-Video`
(HEAD `6b3f4b8`, 27.05.2026) и чтением кода/техотчёта из репозитория:

1. **Лицензия — MIT**, включая веса (`LICENSE`, © 2025 Meituan; раздел «License Agreement» в README).
   Коммерческое использование разрешено — критично для монетизации Reels.
2. **Аудиокодер — Whisper-large-v3** вместо wav2vec2 в 1.0
   (`longcat_video/audio_process/__init__.py`, `pipeline_longcat_video_avatar.py:545`).
   Веса ожидаются в `<checkpoint_dir>/whisper-large-v3`.
3. **Дистилляция 8 шагов**: при `--use_distill --model_type avatar-v1.5` код жёстко ставит
   `num_inference_steps=8`, `text_guidance_scale=1.0`, `audio_guidance_scale=1.0`
   (`run_demo_avatar_single_audio_to_video.py:71-74`). Против 150 NFE у базовой модели
   (50 шагов × 3 forward) — по техотчёту это ~18× меньше forward-проходов.
4. **Геометрия кадра**: v1.5 — 25 fps, `num_frames=93`, `num_cond_frames=13`;
   `480p = 480×832`, `720p = 768×1280` — **оба горизонтальные**.
   Вертикаль 9:16 в демо-скриптах не предусмотрена (проверено в коде, строки 76-88).
5. **Длительность считается сегментами** (проверено скриптом `checks/segment_math.py`):
   первый сегмент 3.72 с, каждый следующий +3.20 с.
   Reel 15 с → 5 сегментов, 30 с → 10 сегментов, 60 с → 19 сегментов.
6. **INT8 действительно экономит VRAM, но не ускоряет** — запущен их собственный модуль
   `longcat_video/modules/quantization.py` на CPU (`checks/int8_check.py`):
   вес блока bf16 → int8 даёт ровно **2.00×** экономии, относительная ошибка выхода **1.05 %**,
   косинус 0.99989. Схема per-channel symmetric weight-only с деквантизацией в forward —
   матмулы остаются в dtype активаций, то есть выигрыша по скорости нет.
7. **Самооценка качества в техотчёте — только human eval, без Sync-C/Sync-D/FID.**
   Таблица 2 отчёта (Fast-вариант, тот самый 8-NFE, который предлагается запускать):
   human-likeness 3.336 (single) / 2.730 (multi), issue rate: rationality 32.4 %,
   **harmony 45.0 %**, stability 4.3 %, consistency 5.9 %.
   То есть по их же разметке почти половина роликов имеет замечания к аудиовизуальной
   согласованности (в которую входит и синхронность губ). Заявленная победа над
   HeyGen / OmniHuman-1.5 / Kling Avatar 2.0 — это A/B-предпочтения на их собственном бенчмарке.

## Что не доказано (`NOT_MEASURED`)

- **Реальное качество lip-sync на аватаре Sofia** — инференс не запускался: в контейнере нет GPU,
  а `huggingface.co` и `modelscope.cn` закрыты egress-прокси (проверено: `CONNECT tunnel failed, 403`).
- **VRAM.** Официальных цифр нет ни в README, ни в техотчёте. Сторонний обзор (VisionStory)
  сообщает про **A800-40GB и только с `--use_int8` + 8-шаговой дистилляцией**, с выгрузкой KV-cache
  в CPU на многосегментных роликах, и про ~**44 с GPU-времени на 1 с готового видео**
  (в пересчёте: Reel 30 с ≈ 24 мин). Маркетинговые сайты обещают «RTX 4090/3090» —
  цифры противоречат друг другу, ни одна не проверена нами.
- Качество и скорость HighSync — код прочитан, но не запускался.

## Практические риски для студии (проверено по коду)

1. **Windows-нативно не заведётся без патчей.** Все демо-скрипты безусловно вызывают
   `dist.init_process_group(backend="nccl")` (7 файлов), а NCCL в Windows-сборках PyTorch нет.
2. **Triton — жёсткий импорт.** `longcat_video/block_sparse_attention/bsa_interface.py:4` делает
   `import triton` на верхнем уровне, и он подтягивается из `modules/attention.py` всегда,
   даже если block-sparse attention выключен. Официальных Windows-колёс Triton нет.
3. **flash-attn 2.7.4.post1** прибит в `requirements.txt`; в issues репозитория его установка —
   самая частая жалоба (#125, #126, июнь 2026).
4. **Вертикальное видео** требует правки кода (см. п.4 выше). В `utils/bukcet_config.py`
   вертикальные бакеты (например `[832, 480]`) существуют, но демо-пайплайн их не использует —
   риск артефактов вне тренировочных разрешений.
5. **Нативной поддержки в ComfyUI нет**: запрос Comfy-Org/ComfyUI#14049 открыт с 22.05.2026
   без ответа мейнтейнеров. Есть только сторонние GGUF/FP8-воркфлоу сообщества (не аудированы).
6. **Известная жалоба на качество**: issue #130 (23.06.2026) — «口型太夸张» (слишком утрированная
   артикуляция). Совпадает с их же harmony issue rate 45 %.

Вывод по рискам: практический контур — **Linux или WSL2 + ≥40 GB VRAM** (или проверенный
INT8/FP8-режим на 24 GB), но не Windows-нативно и не «поставил и поехало».

## Альтернатива, если нужен именно lip-sync, а не генерация видео

**HighSync** (`github.com/saeed5959/high_sync`, MIT, последний коммит 16.08.2026) — правка рта
в существующем видео, прямая замена слоту LatentSync. Проверено по конфигу
`configs/inference/default.yaml`: 512×512 нативно, 25 fps, 20 шагов, CFG 3.5, fp16,
whisper-tiny как аудиокодер, база — SD-image-variations + sd-vae-ft-mse (архитектура EchoMimic).
Такой стек реально влезает в потребительскую карту. Осторожно: это работа одного автора,
без релизов и внешних воспроизведений; метрики в статье самозаявленные.

## Как проверить локально за один прогон (runbook для D:\AI_CONTENT\Sofia)

Выполнять в изолированном окружении, вне production-контура, `local-only / no-publish`.

```bash
# 0. Преконтроль: nvidia-smi, свободная VRAM, отсутствие активного gpu_render
# 1. Только Linux/WSL2
git clone --single-branch --branch main https://github.com/meituan-longcat/LongCat-Video
# 2. Веса (≈ десятки ГБ; нужен и базовый LongCat-Video, и avatar-1.5)
huggingface-cli download meituan-longcat/LongCat-Video-Avatar-1.5 --local-dir ./weights/LongCat-Video-Avatar-1.5
# 3. Минимальный прогон: 1 сегмент (3.72 c), 480p, INT8 + дистилляция
torchrun run_demo_avatar_single_audio_to_video.py \
  --checkpoint_dir=./weights/LongCat-Video-Avatar-1.5 \
  --stage_1=ai2v --input_json=assets/avatar/single_example_1.json \
  --use_distill --model_type avatar-v1.5 --use_int8
# (если одна карта — context_parallel_size оставить 1; NCCL-инициализация всё равно требуется)
```

Критерии приёмки, прежде чем пускать технологию в пайплайн Sofia:

| Проверка | PASS, если |
| --- | --- |
| Пиковая VRAM на 1 сегмент 480p | помещается в карту студии без OOM |
| GPU-время на 1 с видео | ≤ бюджета суточного цикла (эталон для сравнения: 44 с/с) |
| 10 сегментов подряд (Reel ~32 с) | нет OOM на 2-м+ сегменте, нет дрейфа лица и тона |
| Синхронность губ | на аудио Sofia (RU) — слепое сравнение с текущим решением |
| Вертикаль 9:16 | после правки height/width артефактов не больше, чем в горизонтали |
| Лицо персоны | identity держится между сегментами |

Аудио в тестах — русская речь: модели этого класса тренированы преимущественно на английском
и китайском, качество на RU-фонетике надо мерить отдельно, это не переносится из их бенчмарка.
