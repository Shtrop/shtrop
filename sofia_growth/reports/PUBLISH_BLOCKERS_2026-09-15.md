## 2. Блокер A — медиа-хостинг (останавливает внешнюю публикацию)

Из `publish_attempt_journal`:

```
×4  durable public media hosting unavailable: temporary tunnel cannot be
    the sole production media host
×4  hosted media is unreachable: [X509] PEM lib (_ssl.c:4123)
×3  durable public media hosting unavailable: local files cannot be sent
    to Instagram; configure a durable HTTPS media host
```

Graph API забирает медиа по публичному HTTPS-URL. Студия отдаёт его через
временный туннель, который либо недоступен, либо с невалидным сертификатом
(ошибка X509).

Это же объясняет `released_before_external=16`: шестнадцать попыток дошли до
внешнего вызова и сорвались, потому что платформе нечего было забрать.

Сюда же:
- `RECONCILED_REMOTE_MISSING: absent from target Instagram account media list`
- `Graph API error code=9007: Media ID is not available`
- `STALE_PUBLISHING_RECONCILIATION_REQUIRED`

**Влияние:** блокирует публикацию любого типа, включая уже одобренный контент.
**Характер:** инфраструктурный, не контентный. Нужен постоянный HTTPS-хост
с валидным сертификатом вместо временного туннеля.

## 3. Блокер B — caption guard (крупнейший по количеству)

```
×43  bridge: no_caption_passed_guard_semantic_editorial_worldclass
×8   approval demoted to review: gate_failed:world_class_gate;
     evidence_missing:caption_guard; evidence_missing:duplicate;
     evidence_missing:editorial_gate
×4   bridge: owner_style_gate_failed
```

43 отбраковки — ни одна подпись не проходит семантический редакторский гейт
`worldclass`. Восемь раз уже одобренный контент разжалован обратно в review.

**Вопрос, на который нужен ответ перед починкой:** гейт отбраковывает
действительно слабые подписи или порог задан нереалистично? Формулировка
`evidence_missing:*` намекает на второе: гейт требует доказательств, которых
пайплайн ему не передаёт, и это не то же самое, что плохой текст.

## 8. Что это значит для роста

Контент-стратегия сейчас не является узким местом. Любая оптимизация хуков,
каденции и форматов упирается в то, что единственная поверхность с
рекомендациями не публикуется, а публикуемые Stories по определению не дают
нефолловерского охвата.

Пока пункты 1–3 не закрыты, рост подписчиков измерять не на чем: 49 охвата на
публикацию — это не результат контента, а следствие поверхности публикации.

## 9. Границы разбора

- Данные из копий очереди в `docs\...\evidence\`, не из живой базы. Живой
  `content_queue.db` в студии не найден — цифры могут отставать.
- Account-level Insights (подписчики, follows, profile visits) отсутствуют:
  `followers_baseline` и конверсия профиля остаются `NOT_MEASURED`.
- Разбор ничего не меняет и не публикует. Публикация требует отдельного
  решения владельца и прохождения Master Publish Gate.

## 10. Инструмент проверки исправлений

`tools/publish_doctor.py` проверяет каждый блокер и печатает конкретное
исправление. Запускать после каждой правки — он же подтвердит, что блокер снят.

```powershell
# A. Кандидат в production media host — проверяется так же, как это сделает Instagram
python sofia_growth\tools\publish_doctor.py --media-url "https://<домен>/<файл>.mp4"

# B. Caption guard: дефект передачи доказательств или качество текста
python sofia_growth\tools\publish_doctor.py --studio "D:\AI_CONTENT\Sofia"

# C. Соотношение сторон готового медиа и целевые размеры
python sofia_growth\tools\publish_doctor.py --media-dir "D:\AI_CONTENT\Sofia\video_ready"
```

Проверка медиа-хоста повторяет требования Graph API: только HTTPS, доверенная
цепочка сертификата, анонимная отдача, `image/jpeg` для фото и `video/mp4`
либо `video/quicktime` для видео, без сжатия ответа. Ошибка сертификата
распознаётся отдельно — это та же поломка, что в журнале выглядит как
`[X509] PEM lib (_ssl.c:4123)`.

Проверка формата считает фактическое соотношение и печатает обе целевые
пары размеров под ближайшее поддерживаемое. Для Reels обязательно 9:16.
